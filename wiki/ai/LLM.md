# 什么是大语言模型（LLM）

## 定义

用海量语料预训练、参数到百亿千亿规模、自回归生成文本的统一模型。

- **本质**：预测下一个 token（Causal Language Model, CLM）
- **统一接口**：所有 NLP 任务都被 Prompt + 续写收编
- **In-Context Learning**：Prompt 里给几个例子，模型无需更新参数就能学会新任务

## LLM vs 传统 NLP

| 维度 | 传统 NLP | LLM |
|---|---|---|
| 任务方式 | 一任务一模型 pipeline | 一个模型干所有事 |
| 输出范式 | 判别式（标签/概率） | 生成式（文本） |
| 能力来源 | 显式监督训练 | 大规模预训练 + 涌现 |
| 工程着力点 | 数据标注/特征工程 | Prompt Engineering / RAG / Agent |

## 涌现能力

**定义**：某项能力在小模型上几乎看不到，规模到临界点后突然表现。

- **典型例子**：多步算术、上下文学习、跨语言迁移
- **临界规模**：通常 50B-100B
- **Mirage 挑战**：部分"涌现"可能是评估指标不连续性造成的测量假象——当指标是精确匹配率时，模型从"完全不会"到"偶尔做对"会表现为突然跳跃，但实际能力可能是平滑增长的

## 幻觉

详见 [[AIHallucination]]。

**定义**：模型生成与训练事实不一致的内容，但语言上看起来流畅合理。

### 三大根因

1. **训练数据层**：语料本身有错误
2. **生成机制层**：next-token prediction 不是数据库，模型是在"续写"而非"检索"
3. **对齐目标层**：SFT + RLHF 训练中"自信回答"比"我不知道"得分更高

### 三类幻觉

- **事实性幻觉**：编造不存在的事实（如虚构论文、伪造历史事件）
- **推理性幻觉**：推理链条中引入错误前提或逻辑跳跃
- **上下文不一致**：回答与用户提供的上下文或前文矛盾

### 缓解方案

- **训练层**：拒答样例、校准训练
- **推理层**：[[CoT]]、Temperature 调低、Self-Consistency
- **系统层**：[[RAG]]、后处理事实核查、强制带引用

**核心结论**：幻觉不可能完全消除，工程目标是降低发生率 + 让用户能识别。

## 主流大模型选型

### 国内候选

| 模型 | 特长 | 适合场景 |
|---|---|---|
| DeepSeek | 推理和性价比 | 高频分析、代码辅助、成本敏感 |
| Qwen | 中文语境、工具调用、长上下文 | 主调度、文档理解、RAG 汇总 |
| 豆包 | 工程生态、并发能力 | 高频文本处理、客服、内容生成 |

### 海外标杆

| 模型 | 特长 | 注意事项 |
|---|---|---|
| GPT-5.5/o 系列 | 复杂推理、代码、多模态 | 数据出境合规 |
| Claude Sonnet/Opus | 长文本、代码、Agent 调度 | 合规审批、成本 |

### Model Routing 策略

- **主调度/格式严格节点**：选结构化输出稳定的模型
- **高频推理/数据清洗/摘要节点**：选推理能力和 token 单价均衡的模型
- **特别难的问题**：路由给能力更强但更贵的模型
- **敏感数据链路**：优先走合规可控的国内模型

## 评测指标

### 主流 Benchmark

| Benchmark | 测什么 |
|---|---|
| MMLU / MMLU-Pro | 综合知识广度 + 推理 |
| HumanEval / MBPP | 代码生成 |
| SWE-bench | 真实软件工程 |
| GSM8K / MATH | 数学推理 |
| MT-Bench | 多轮对话 |
| Chatbot Arena | 用户偏好 |
| tau-bench | Agent / Tool Use |

### Benchmark 系统性缺陷：数据污染

模型训练数据覆盖互联网大部分公开内容，Benchmark 题目可能被"见过"。排行榜高的模型实际用起来不一定更好。

### 业务测试集构建

1. **采样**：从真实用户请求采样 50-200 条黄金测试集
2. **评分方式**：
   - 客观任务：程序验证
   - 主观任务：LLM-as-Judge
   - 人工抽查 10-20% 校准
3. **评估闭环**：
   - 离线：业务测试集
   - 线上：用户满意度、任务完成率、会话放弃率
