### CoT 思维链

CoT（Chain of Thought）思维链是一种让 AI 像人类一样 "思考" 的技术，帮助 AI 在处理复杂问题时能够按步骤思考。对于复杂的推理类问题，先思考后执行，效果往往更好。而且还可以让模型在生成答案时展示推理过程，便于我们理解和优化 AI。

### 为什么 CoT 有效？

LLM 的工作原理是根据输入一个 token 一个 token 地往后预测。当它「一口气」预测答案时，中间的推导步骤都是隐式的，误差会在中间某个暗处悄悄累积，最终暴露在答案里。

CoT 的核心思想是：让 LLM 先把推理步骤写出来，再给答案。为什么加一句话就有效？

本质是因为 LLM 的输出是顺序生成的，先写出来的推理内容会进入上下文，成为后续生成的依据。当 LLM 先写出「第一步：A 市值是 B 的 1.2 倍，所以 A > B」这句话之后，这个推导结论就进入了上下文，下一步的预测建立在这个明确写出的正确基础上，而不是靠它在脑子里「暗中维持」这个中间状态。

就像笔算，纸上的每一行数字都在帮你记住上一步算到哪了。

### CoT 的两种触发方式

**Zero-shot CoT**：
- 做法：直接在 prompt 末尾加上「让我们一步步思考」这句话
- 优点：零成本、即插即用
- 缺点：LLM 的推理格式和深度完全靠它自己发挥，不太稳定，有时候会写得很详细，有时候又跳步

**Few-shot CoT**：
- 做法：在 prompt 里给几个带有完整推理过程的例子，让 LLM 照着这个格式来模仿
- 优点：效果更稳定，特别适合输出格式要求比较固定的场景
- 缺点：需要提前准备高质量的示例，而且示例本身也会占用 token

### CoT 的局限

CoT 有一个根本性的局限：**它是纯文字推理，没有办法和外部世界交互**。

推理过程再完整，也拿不到实时数据，不能执行计算，不能访问数据库。如果你问 LLM「现在苹果公司的市值是多少？」，它只能根据训练数据里的知识回答，而那些知识可能已经过时好几个月了。

严格说，CoT 框架里不是不能调工具（你可以用 Prompt 让它生成一个「建议调用 API」的文本），但 CoT 的设计本身没有把推理和工具调用交织在一起，接工具需要你自己在外面额外胶水。

### CoT vs ReAct

| 维度 | CoT | [[ReAct]] |
| --- | --- | --- |
| 推理方式 | 纯文字推理 | 推理 + 工具调用交织 |
| 外部交互 | 无法直接交互 | 可以调用工具获取实时数据 |
| 适用场景 | 纯逻辑推理题 | 需要外部信息的任务 |
| 实现复杂度 | 低，改 prompt 即可 | 中，需要工具调用框架 |

ReAct 就是在 CoT 的基础上加了「行动」，让 LLM 交替输出思考和工具调用，每次行动后再根据结果继续思考，形成一个循环。

### CoT vs ToT vs GoT

这三种是规划能力方向上依次演进的方案：

**CoT**：只有一条推理路径，一旦走错方向，整条链就歪了，没有任何纠偏机制。

**ToT（Tree of Thoughts）**：同时探索多条推理路径，边探索边评估边剪枝，最终选出最优路径。代价是多次 LLM 调用，典型设置下成本是 CoT 的 3-5 倍。

**GoT（Graph of Thoughts）**：把推理结构从树换成图，允许不同路径的中间结果合并、复用。落地复杂度很高，目前主要还是学术研究场景。

### CoT 在 Agent 中的应用

在 [[AIAgent|Agent]] 系统中，CoT 是推理模式的基础层：

- **ReAct**：在 CoT 基础上加了「行动」，形成 Thought -> Action -> Observation 循环
- **Plan-and-Execute**：用 CoT 生成完整的执行计划，再分步执行
- **Reflection**：用 CoT 生成评估意见，检查输出质量

### 什么时候用 CoT？

**适合用 CoT 的场景**：
- 纯逻辑推理题，不需要外部数据
- 数学计算、逻辑判断
- 需要展示推理过程的场景
- 作为 Agent 的基础推理能力

**不适合用 CoT 的场景**：
- 需要实时信息的任务
- 需要调用外部工具的任务
- 复杂的多步骤任务，容易跑偏
