# LLM Gateway（大模型网关）

## 概述

LLM 网关是架在**应用层**和**模型 API** 之间的中间层，统一管理所有大模型的调用请求。它屏蔽了底层模型的差异，为上层应用提供一致的使用体验。

## 没有网关时的痛点

| 问题 | 具体表现 |
|------|---------|
| API Key 散落 | Key 硬编码在各服务中，泄漏风险高 |
| 重复劳动 | 每个服务各自实现重试、限流、降级逻辑 |
| 成本黑箱 | 无法追踪各团队/项目的 Token 消耗 |
| 灵活性差 | 切换模型需要修改业务代码 |

## 核心功能

### 1. 多模型统一接口

将不同厂商的 API 抽象为统一接口，切换模型对业务代码**完全透明**。

```
应用 → LLM Gateway → OpenAI / Anthropic / 通义千问 / ...
```

### 2. API Key 集中管理

所有模型 API Key 在网关层统一存储和管理，应用层只需持有网关的访问凭证，大幅降低 Key 泄漏风险。

### 3. 负载均衡与故障转移

支持多活策略：当某个模型提供商出现故障或限流时，自动将请求切换到备用模型，保障服务可用性。

### 4. 限流与配额管理

按团队、项目或接口维度设置 Token 日预算，防止单一消费者耗尽资源。

### 5. 成本追踪与可观测性

记录每次调用的 Token 用量、延迟、成本等指标，提供可视化的成本分析面板。

### 6. Prompt 安全与内容过滤

在请求到达模型之前，对 Prompt 进行安全审查和敏感内容过滤。

### 7. 语义缓存

用向量相似度匹配语义相近的问题，命中缓存时直接返回历史答案，跳过 LLM 调用。

#### 语义缓存的工作原理

```
用户提问 → 问题向量化 → 向量数据库相似度搜索
                              ↓
                        相似度 ≥ 阈值 → 返回缓存答案
                        相似度 < 阈值 → 调用 LLM → 结果写入缓存
```

#### 语义缓存注意事项

- **相似度阈值**：通常设置在 **0.85 - 0.95** 之间，过低会导致误命中，过高会降低缓存命中率
- **缓存有效期**：需要根据业务场景设定 TTL，避免返回过时信息

## 常见网关框架对比

| 框架 | 特点 |
|------|------|
| **LiteLLM** | 开源，支持 100+ 模型提供商，Python 生态友好，社区活跃 |
| **Bifrost** | 国产开源网关，支持国内模型厂商 |
| **PortKey** | 提供 Prompt 管理和 A/B 测试能力 |
| **Kong AI Gateway** | 基于 Kong 网关，适合已有 Kong 基础设施的企业 |
| **One API** | 轻量级，支持多种模型聚合和分发 |
