# LLM 训练与微调

> 大语言模型的训练体系——从预训练到对齐，从全量微调到参数高效方法。

## LLM 三阶段训练框架

LLM 的训练可以类比为人才培养的三个阶段：

| 阶段 | 类比 | 核心目标 |
|---|---|---|
| 预训练 | 读万卷书（基础知识） | 获得语言能力和世界知识 |
| SFT | 面试培训（学会问答格式） | 学会按指令对话 |
| 对齐 | 职业素养（好好说话） | 输出符合人类偏好 |

### 第一阶段：预训练（Pretraining）

- **数据来源**：Common Crawl、GitHub、维基百科、图书、论文、新闻
- **数据清洗**：去重、过滤低质量、识别语言、剔除有害信息
- **训练目标**：CLM（Causal Language Modeling，预测下一个 token）
- **计算开销**：[[Transformer]] 架构下，[[LLM]] 如 GPT-3 约需 $3.14 \times 10^{23}$ FLOPs
- **结果**：具备语言能力和世界知识，但只会续写，不会对话

### 第二阶段：SFT（Supervised Fine-Tuning）

- **目的**：把续写机器改造成对话机器
- **数据格式**：`(指令, 期望回答)` 对
- **关键原则**：质量 > 数量——几千条高质量数据 > 几十万条粗糙数据
- **数据多样性**：问答、写作、代码、角色扮演、数学推理、翻译

### 第三阶段：对齐（Alignment）

对齐阶段的目标是让模型输出符合人类偏好，"好好说话"。

#### RLHF（Reinforcement Learning from Human Feedback）

1. 人类标注偏好排序
2. 训练奖励模型（Reward Model）
3. PPO 强化学习优化策略

效果上限高，但工程复杂、训练不稳定。

#### DPO（Direct Preference Optimization）

绕过奖励模型，直接用 `(问题, 好回答, 差回答)` 三元组训练。简单稳定，是当前最主流的对齐方法之一。

#### GRPO（Group Relative Policy Optimization）

[[LLM]] 厂商 DeepSeek 提出，PPO 的改进版——砍掉 Value Model，用组内归一化估计优势函数（Advantage），降低工程复杂度的同时保持接近 PPO 的效果。

#### 拒绝采样（Rejection Sampling）

生成多个候选回答 -> 奖励模型筛选高分 -> 再做 SFT。实现极简，训练极稳。

#### RLAIF（RL from AI Feedback）

用 AI 替代人类标注偏好，降低标注成本。

#### 五类方法对比

| 方法 | 是否用 RL | 维护模型数 | 训练稳定性 | 效果上限 | 典型应用 |
|---|---|---|---|---|---|
| RLHF | 是 | 4（策略+参考+奖励+价值） | 低 | 高 | InstructGPT, Claude |
| DPO | 否 | 2（策略+参考） | 高 | 中高 | Llama 3, Qwen |
| GRPO | 是 | 2（策略+参考） | 中 | 高 | DeepSeek-R1 |
| 拒绝采样 | 否 | 2（策略+奖励） | 极高 | 中 | Llama 2-Chat |
| RLAIF | 是 | 4 | 低-中 | 中高 | Gemini |

#### 组合使用

实际训练中，多种方法常常组合使用：

- **Llama 2-Chat**：SFT -> 拒绝采样 -> PPO
- **DeepSeek R1**：SFT -> GRPO -> 拒绝采样 -> SFT -> GRPO

## 微调方案

### 前置判断：微调是最后手段

微调不是第一选择，优先级如下：

`Prompt + Few-shot > System Prompt > [[RAG]] > 微调`

#### 真正需要微调的三种场景

1. **持续特殊风格输出**：如品牌语调、特定写作风格
2. **稳定掌握特定任务模式/内部术语**：如公司内部流程、专业领域术语
3. **用小模型替代大模型省成本**：通过微调让小模型在特定任务上达到大模型水平

#### 不适合微调

- 补充经常变化的事实知识 -> 应使用 [[RAG]]

### 全量微调 vs LoRA vs QLoRA

| 维度 | 全量微调 | LoRA | QLoRA |
|---|---|---|---|
| 可训练参数 | 全部 | ~0.1%-1% | ~0.1%-1% |
| 显存 (7B) | 80GB+ | ~20GB | <10GB |
| 推理额外开销 | 无 | 无（可合并） | 无（可合并） |
| 灾难性遗忘 | 高 | 低 | 低 |
| 部署灵活性 | 低 | 高（一个基底 + 多套 LoRA） | 高 |
| 效果上限 | 最高 | 接近全量 | 接近全量 |

### LoRA 五大优点

1. **推理零开销**：LoRA 权重可合并回基础模型，推理时不增加任何延迟
2. **部署灵活**：模块化插拔，一个基底模型搭配多套 LoRA 适配不同任务
3. **灾难性遗忘风险低**：只训练少量额外参数，基础能力保持完整
4. **训练更稳定**：小参数空间更容易优化
5. **权重可组合性**：多套 LoRA 权重可线性组合

### QLoRA

QLoRA = NF4 量化基础模型 + LoRA。一张 4090（24GB 显存）即可微调 7B 甚至 13B 模型，大幅降低硬件门槛。

### 两个正交维度

微调方案实际上由两个正交维度决定：

- **"改哪些参数"**：全量 / LoRA / QLoRA
- **"学什么目标"**：SFT / DPO

两个维度正交，可任意组合。例如 `LoRA + SFT`、`QLoRA + DPO`、`全量 + RLHF` 等。

### 实战选型矩阵

| 资源场景 | 推荐方案 |
|---|---|
| 个人 / 资源受限 | QLoRA + SFT（一张 4090） |
| 中小企业 / 几张 A100 | LoRA + SFT |
| 需偏好对齐 | LoRA + SFT -> LoRA + DPO |
| 大厂 / 顶级效果 | 全量微调 + SFT + RLHF |

## Scaling Law

### 幂律缩放

模型损失值随参数量 $N$、数据量 $D$、算力 $C$ 按幂律下降：

$$L(N) \propto N^{-\alpha}, \quad L(D) \propto D^{-\beta}, \quad L(C) \propto C^{-\gamma}$$

### Chinchilla 缩放定律

固定算力下，参数和数据按 **1:20** 配比时损失最低。即每增加 1 个参数，需要约 20 个 token 的训练数据。

### Llama 3 时代的突破

Llama 3 的参数-数据比达到 **1:1875**，远超 Chinchilla 推荐的 1:20，说明数据量远超 Chinchilla 推荐值仍可持续提升模型性能。

### 涌现能力（Emergent Abilities）

某些能力在小模型上完全看不到，但规模超过临界点后突然出现：

- 多步算术推理
- In-Context Learning（[[Prompt]] 中少量示例学习）
- 跨语言泛化

### Mirage 挑战

部分"涌现"可能是评估指标不连续性造成的测量假象（Mirage），而非模型能力的真正跃迁。

### 天花板

- **数据墙**：高质量公开文本估计仅剩 10T-50T token
- **算力墙**：训练前沿模型所需算力持续指数级增长
