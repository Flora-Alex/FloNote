# Agent 记忆系统

[[agentMemory]] 总结 Agent 的记忆与状态管理。记忆不是把所有历史对话塞进 prompt，而是把对任务有用的信息结构化、压缩、检索和更新。

## 记忆分层

常见记忆类型：

- 感知记忆：当前输入、工具观察结果、临时环境状态。
- 短期记忆：当前会话消息、当前计划、最近工具结果。
- 长期记忆：跨会话保存的事实、经验、偏好。
- 实体记忆：用户、订单、项目、文件、业务对象等结构化实体。
- 变量记忆：Function Calling 中的关键 ID、last_result、状态字段。

## 短期记忆

短期记忆通常就是当前上下文窗口内的 message list，包括：

- 用户请求。
- Agent 思考和计划。
- 工具调用记录。
- 工具返回结果。
- 当前任务状态。

风险：上下文窗口有限，长任务会膨胀，需要压缩和裁剪。

## 长期记忆

长期记忆用于跨会话复用信息。

类型：

- 情节记忆：发生过什么任务、什么时候发生、结果如何。
- 语义记忆：稳定事实、用户偏好、项目知识。
- 程序记忆：如何完成某类任务的流程经验。

存储方式：向量库、关系数据库、文档库、文件系统。

## 实体记忆

实体记忆保存结构化对象：

- 用户偏好。
- 业务 ID。
- 订单号。
- 航班号。
- 文件路径。
- 项目配置。

实体记忆比自然语言摘要更适合工具调用，因为它能直接填入参数。

## Function Calling 中的变量记忆

工具链常需要跨轮复用变量：

```text
state = {
  user_id,
  order_id,
  last_search_result,
  selected_file,
  current_plan
}
```

实践建议：

- 关键 ID 结构化保存。
- 工具调用前检查 required 参数。
- 缺参时追问，而不是编造。
- last_result 要有类型和来源。

## 记忆压缩

常见压缩方式：

- 滑动窗口：保留最近 N 轮。
- 摘要压缩：把历史对话压成摘要。
- 层级摘要：长任务分阶段总结。
- 重要性过滤：只保留关键事实。
- 结构化抽取：把偏好、实体、任务状态抽成字段。

## 记忆风险

- 过期记忆导致错误决策。
- 隐私泄露。
- 无关记忆污染当前任务。
- 模型误用历史工具结果。
- 向量检索召回噪声。
- 长期记忆与当前用户指令冲突。

## 记忆设计原则

1. 先区分短期任务状态和长期用户偏好。
2. 工具参数优先结构化保存。
3. 长期记忆必须可删除、可审计、可过期。
4. 召回记忆要有来源和置信度。
5. 记忆进入 prompt 前要过滤，避免污染模型。
